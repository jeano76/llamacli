# laya fast decision (System 1 sidekick)

This machine also runs `laya` — a small, non-reasoning CPU model (`convaiinnovations/laya`)
exposed over HTTP at `http://127.0.0.1:8000`. It answers narrow, typed questions
(`choice` / `score` / `noul`) in well under a second, versus tens of seconds for a full
reasoning turn on the main model (Ornith). Use it as an **advisory shortcut**, never as
the sole basis for anything consequential or destructive.

## When to use this

Only for a genuinely quick classification/triage judgment that would otherwise cost a
full slow-model turn to reach — e.g.:
- Is this error message/output transient noise or something that actually needs fixing?
- Does this look urgent/risky enough to flag before proceeding?
- Given a short list of options, which one best matches the situation?

Do NOT use it for anything that needs real reasoning, code understanding, or judgment
with consequences (never let it decide whether to run a destructive command, whether a
fix is correct, or anything you'd normally think through yourself). Treat its answer as
one extra data point, not a decision.

## How to call it

Run via the shell tool, **always with `--no-check`** (without it, a missing/offline
laya server triggers an interactive `y/N` install prompt that will hang indefinitely —
there is no terminal attached to answer it):

```bash
python3 /home/jeano/llamacli_plugin/scripts/laya_integration.py fastcheck \
  --text "<a short, self-contained yes/no or multiple-choice question>" \
  --no-check
```

- Exit code 0 with an answer printed to stdout = laya responded. The answer includes
  the chosen option (with a probability) or a 0–1 score, plus which internal checkpoint
  answered and why.
- Exit code 1 (server not running/unreachable, or the request failed/timed out) = laya
  is unavailable right now. This is expected and NOT an error to report or retry —
  silently fall back to reasoning about it yourself and continue normally.
- Hard-capped at ~3 seconds internally, so it can never meaningfully stall a turn.

## Short-circuit verdict (optional fast path)

`fastcheck` also supports asking laya directly whether you may proceed without the full
Ornith turn. This is **off by default** (`shortCircuit: false`) because skipping the
reasoning model only stays safe when laya is both *confident* and *sure the task is quick*.

```bash
python3 /home/jeano/llamacli_plugin/scripts/laya_integration.py fastcheck \
  --text "<narrow yes/no or multi-choice question>" \
  --decision yes \
  --no-check
```

- Pass `--decision no` to ask the opposite (proceed vs. don't-proceed).
- On exit code 0, read only the last line: `verdict: {yes|no|n/a} | act_prob=X.XX conf=Y.YY`.
  - `verdict: yes` means laya both answered "yes" and its combined confidence met the
    bar (`confidenceThreshold`, default 0.7). You may short-circuit — take laya's answer as
    final and skip Ornith entirely.
  - `verdict: no` means it either said "no", or its confidence was too low to trust a skip
    → treat this like an ordinary advisory result: fall back to the full reasoning turn.
  - `verdict: n/a` means laya couldn't decide — same as `no`, fall back to Ornith.

The gate requires **both** conditions (see §4 below): act_probability ≥ threshold AND
confidence ≥ threshold. When either fails, never short-circuit — the reasoning model is
still there for you.

## Notes

- No installation/startup is attempted by this skill — `--no-check` means it either
  answers or fails silently. If you want to check whether laya is set up on this
  machine at all, `python3 /home/jeano/llamacli_plugin/scripts/laya_integration.py status`
  prints `{enabled, installed, running, swapFreeKb, ramFreeKb}` as JSON (read-only, safe).
- laya's `.llamacli/config.yaml` `laya:` section controls behavior:
  - `questionType` — default question framing (`noul` / `choice` / `score`).
  - `criteria` — free-text rubric attached to `choice`/`score` questions.
  - `labels` — option labels for `choice`/`score`.
  - `baseUrl` — laya HTTP endpoint (default `http://127.0.0.1:8000`).
  - `timeoutSeconds` — internal hard cap on the request (default `3`).
  - `actProbabilityThreshold` / `confidenceThreshold` — the two bars for short-circuit.
  - `shortCircuit` — enable/disable the fast path (`false` by default).
- This skill touches no llamacli core code; it's a plain shell call to a standalone
  script that degrades to a no-op whenever laya isn't available.
