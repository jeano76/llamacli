# laya fast decision (System 1 sidekick)

This machine also runs `laya` — a small, non-reasoning CPU model (`convaiinnovations/laya`,
ModernBERT-large, ~421M params) exposed over HTTP at `http://127.0.0.1:8000`. It answers
narrow, typed questions (`choice` / `score` / `noul`) in well under a second (实测 ~0.55초),
versus tens of seconds for a full reasoning turn on the main model (Ornith). Use it as an
**advisory shortcut**, never as the sole basis for anything consequential or destructive.

> 설계/검토 근거: 이 스킬은 `docs/skill-integration-review.md`에 나온 검토(1~7항)와 그
> 최종 권고(MVP)에 따라 구현되었습니다. 핵심 권고는 **"merge-style gate + `/fastcheck` 단축
> 경로(b)는 off-by-default" **입니다 — 즉 laya로 내린 판단은 Ornith 호출 컨텍스트를 보강하는
> 조언으로 쓰이고, 명확히 확정된 경우에만 Ornith 호출을 생략하는 단축이 가능하지만 이 단축은
> 기본적으로 꺼져 있습니다.

## When to use this

Only for a genuinely quick classification/triage judgment that would otherwise cost a
full slow-model turn to reach — e.g. (검토 4번 적용处长 후보):
- Is this error message/output transient noise or something that actually needs fixing?
- Does this look urgent/risky enough to flag before proceeding?
- Given a short list of options, which one best matches the situation?
- Is this diff/commit small enough to skip a long summary, or does it need one?

Do NOT use it for anything that needs real reasoning, code understanding, or judgment
with consequences (never let it decide whether to run a destructive command, whether a
fix is correct, or anything you'd normally think through yourself). Treat its answer as
one extra data point, not a decision.

## How to call it

### Default: advisory `fastcheck` (always use `--no-check`)

Run via the shell tool, **always with `--no-check`** (without it, a missing/offline
laya server triggers an interactive `y/N` install prompt that will hang indefinitely —
there is no terminal attached to answer it):

```bash
python3 /home/jeano/llamacli_plugin/scripts/laya_integration.py fastcheck \
  --text "<a short, self-contained yes/no or multiple-choice question>" \
  --no-check
```

- Exit code 0 with an answer printed to stdout = laya responded. The answer includes
  the chosen option (with a probability) or a 0–1 score, plus which internal checkpoint
  answered and why. Use it as advisory context for Ornith — do NOT treat it as truth.
- Exit code 1 (server not running/unreachable, or the request failed/timed out) = laya
  is unavailable right now. This is expected and NOT an error to report or retry —
  silently fall back to reasoning about it yourself and continue normally.
- Hard-capped at ~12 seconds internally (see `TIMEOUT_SECONDS`), so it can never meaningfully stall a turn.

### Optional: short-circuit `/fastcheck --decision yes|no`

If the question is a **bare, low-stakes decision** where laya's answer is already
high-confidence (its `probability ≥ 0.85` **and** `confidence ≥ 0.70`), you may skip the
Ornith turn entirely and act on laya alone:

```bash
python3 /home/jeano/llamacli_plugin/scripts/laya_integration.py fastcheck \
  --text "Is this error message transient noise?" \
  --decision yes --no-check
```

- If both thresholds are met, laya prints `SHORT-CIRCUIT: <label> (probability=…, confidence=…)`.
  You may then act directly on that verdict — no Ornith turn needed.
- If either threshold is **not** met, it does NOT print SHORT-CIRCUIT; instead it tells you
  to run System 2 (Ornith) for an honest read. This is the normal path.
- This short-circuit is a safety tool, not a speed hack: only use it when the cost of being
  wrong is low. `decision` must be exactly `yes` or `no`.

## Notes on safety & configuration (검토 2/3/5/7항)

- **Resource gate:** before calling laya this skill checks the machine's swap-free memory
  (`SwapFree`, in KiB from `/proc/meminfo`) via the `-s/--swap-min` flag (default 500,000 KiB).
  If below that it prints `SKIP_GATE: ... free_swap=… < threshold …` and returns exit 0 as a
  no-op — this mirrors the past OOM incident where a CPU model's RAM use starved Ornith. It
  also refuses to start when RAM is critically low (`-r/--ram-min`, default 1 GiB). **SwapFree
  is the real gate, not total RAM** (see 附록 A of the review).
- **Degrade gracefully:** a missing/offline server or a timeout is exit 1 + "not available".
  Never report or retry — silently continue with Ornith. This matches the skill philosophy that
  failure must never break llamacli's core behaviour.
- **On/off switch (`laya.enabled`):** when `enabled: false` (or the section missing), the
  script exits immediately as a silent no-op before any health probe or swap check — fully
  off, not even "quietly checking". Toggle is read once per invocation; no runtime toggle needed.
- **CPU-only by design:** laya runs CPU mode (`run-server.sh` hard-codes this after the
  incident where GPU VRAM contention threatened Ornith's `-c 24576`). Do not try to force
  GPU — it would compete with Ornith for the shared ~8GB and risk cascading context reduction.
- **No auto-install:** this skill never installs or starts laya (`--no-check` guarantees it).
  If laya isn't present, `status` reports `{installed:false}`; installing requires explicit
  user consent per the review (6항) — do not auto-provision silently.

## Related commands

- `python3 /home/jeano/llamacli_plugin/scripts/laya_integration.py status`
  prints `{enabled, installed, running, swapFreeKb, ramFreeKb}` as JSON — read-only, safe.
- `python3 /home/jeano/llamacli_plugin/scripts/laya_integration.py gate --text "<…>"`
  runs the **merge-style gate**: it emits a laya judgment (for enriching Ornith's context) and,
  only if short-circuit is enabled in config AND both thresholds pass, a SHORT-CIRCUIT line.

## Config reference (`.llamacli/config.yaml` `laya:` section)

```yaml
laya:
  baseUrl: "http://127.0.0.1:8000"   # laya server endpoint
  timeoutSeconds: 3                   # hard cap for the gate/fastcheck request
  questionType: "noul"                # noul | choice | score — how fastcheck frames --text
  actProbabilityThreshold: 0.85       # short-circuit: laya's own probability floor (shortCircuit on)
  confidenceThreshold: 0.7            # short-circuit: minimum required confidence (shortCircuit on)
  enabled: false                       # master switch — when false, silent no-op (no probe at all)
  shortCircuit: false                  # allow-listed skip of the Ornith turn; OFF by default
```

- `enabled: false` is the safest state and the effective default — with it off, calling any
  subcommand is a harmless no-op even if laya happens to be running.
- `questionType`, `criteria`, `labels`, `baseUrl` control how `fastcheck` frames its default
  question from `--text`; in practice `--text` alone is usually enough.
- `shortCircuit` stays off unless you explicitly turn it on; when on, BOTH thresholds must be
  met for the short-circuit verdict to appear (see `/fastcheck --decision` above).

This skill touches no llamacli core code; every subcommand is a plain shell call to a standalone
script that degrades to a no-op whenever laya isn't available or the resource gate fails.
