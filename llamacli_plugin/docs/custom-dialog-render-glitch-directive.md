# 커스텀 Y/N 확인창 렌더링 겹침 버그

## 증상 (직접 재현/캡처된 화면)

리눅스(GNOME Terminal, xterm-256color) 세션에서, laya 연동용으로 추가한 것으로
보이는 커스텀 확인창("이어서 진행할까요? Y(예) / N(아니오) 를 입력해주세요.")이
뜰 때, 그 직전까지 로그에 있던 텍스트(예: `typed-decisions`/QTYPES 관련 조사
내용)와 새로 그려지는 확인창 텍스트가 **한 화면에 겹쳐서** 보입니다:

```
    "instru "typed-decisions",   # ← 이게 버그입니다
ns": instructi"
이어서 진행할까요? Y(예) / N(아니오) 를 입력해주세요.
╭──────────────────────────────────────────────────────────────────────────────────────────────────────────────────╮
    "instructions": instructi" ( │ ← 이게 버그입니다
```

Windows가 아니라 리눅스에서도 재현됐고, llamacli 코어의 최신 빌드(커서 숨김/
ANSI 호환성/재렌더링 수정 다 반영된 버전)로 재시작한 뒤에도 나타났습니다 — 즉
llamacli 코어 쪽 문제가 아니라 **이 프로젝트에서 추가한 커스텀 다이얼로그
렌더링 코드**의 문제로 보입니다.

## 근본 원인 추정

이전 프레임의 텍스트가 새 프레임보다 길었는데, 화면을 완전히 지우지 않고
그 위에 짧은 새 텍스트만 덧그려서 이전 줄의 꼬리 부분이 그대로 남아있는
전형적인 "부분 지우기 누락" 패턴입니다. Ink의 기본 증분(diff) 렌더링은
보통 각 줄 끝에 지우기(clear-to-end-of-line)를 같이 하지만, 이 확인창이
별도의 raw stdout 쓰기나 자체 렌더링 경로를 쓰고 있다면 그 처리가 빠졌을
가능성이 높습니다.

## 요청

1. 이 Y/N 확인창을 그리는 코드를 찾아서, **확인창을 띄우기 직전에 화면을
   한 번 완전히 지우고(clear) 다시 그리도록** 하세요. 이 다이얼로그는
   자주 뜨는 게 아니라서(사용자 확인이 필요한 순간에만) 매번 전체 클리어를
   해도 성능 문제는 없습니다 — 오히려 여기서는 안전한 선택입니다.
2. 만약 Ink의 표준 렌더링 경로(React 컴포넌트 트리 안에서 `<Box>`/`<Text>`로
   그리는 방식)를 쓰고 있다면 애초에 이 문제가 안 생겨야 정상이니, 혹시
   `process.stdout.write()`로 직접 쓰는 별도 경로가 있는지 확인하세요 —
   있다면 그게 원인일 가능성이 큽니다.
3. 수정 후 실제로 긴 로그가 화면에 떠 있는 상태에서 확인창을 띄워보고,
   겹침 없이 깨끗하게 그려지는지 재현 테스트로 확인하세요.
